AI FinOps / TokenOps / Unit economics

Make every token
answer for itself.

A field guide for understanding, allocating, and improving the economics of AI workloads. Start with a measurable unit of value, then connect it to usage, quality, and cost.

01 / Operating picture

Three things to make visible

AI cost control starts with the relationship between workload, measured usage, and an outcome someone values.

01 / MeasureUsage

Capture provider, model, input/output tokens, cache usage, request outcome, and workload identity.

02 / AttributeOwner

Join usage to the product, team, environment, and feature that caused it; preserve unknowns instead of guessing.

03 / ImproveValue

Compare cost with a quality and business outcome, not token reduction alone.

02 / Unit economics

03 / Metering

Build a trustworthy usage record

Provider invoices and application telemetry answer different questions. Reconcile them instead of expecting either one to be the whole ledger.

Instrument

Capture dimensions that explain spend

Record provider-reported usage alongside an application request identifier and stable workload context.

  • Provider, endpoint, model, region, and timestamp
  • Input, output, cached, and modality-specific units when available
  • Team, product, feature, environment, and outcome
  • Retry, timeout, fallback, and tool-call relationships
Reconcile

Keep estimates distinct from charges

Token telemetry estimates consumption. Provider billing records apply contract rates, discounts, minimums, credits, and adjustments.

  • Store raw usage and pricing version separately
  • Track unattributed cost as an explicit category
  • Compare usage totals to invoice exports at matching granularity
  • Document currency, tax, and allocation policy
Schema

Use shared telemetry conventions

OpenTelemetry's GenAI semantic conventions define common attribute and metric names. Treat evolving conventions as versioned schemas.

Privacy

Meter without collecting prompts by default

Usage attribution usually needs identifiers and counts, not prompt or completion text. Apply data minimization, access controls, retention limits, and redaction.

04 / Optimization

Reduce waste, protect quality

Every cost intervention should have an owner, a measured baseline, and a quality guardrail.

Context

Send only useful context

Remove duplicated instructions and irrelevant history, retrieve selectively, and cap context with a quality-tested policy.

Output

Constrain completion length

Use task-appropriate output limits and structured formats. Measure truncation, retries, and task success as well as tokens saved.

Cache

Reuse work where semantics allow

Evaluate prompt caching, application caching, and batch processing against freshness, privacy, cache eligibility, and provider-specific prices.

Evaluation

Route by task difficulty

Start with representative evaluations and escalation rules. A cheaper model is not cheaper if it creates extra retries, review, or failure cost.

05 / Routing & hosting

Compare total delivered cost

Hosted API, managed cloud, self-hosted, and hybrid deployments expose different cost and operational risks.

Hosted API

Price usage; verify every meter

Check model-specific input, output, cached, batch, and modality rates, plus context limits, region availability, and service terms.

Self-hosted

Include idle and people costs

Model accelerator-hours, utilization, memory fit, redundancy, storage, networking, engineering, and on-call overhead. The break-even point depends on actual throughput and utilization.

Hybrid

Route with observable policy

Make model choice explainable and log route decisions. Include fallback rates, quality, latency, residency, and provider concentration in the comparison.

Decision

Use cost per successful task

Compare full-system cost per accepted result, including retries and human review, rather than comparing list price per token in isolation.

06 / Budgets & controls

Govern the spend path

Forecasts, limits, and alerts need clear owners and behavior when a threshold is reached.

Forecast

Forecast from workload drivers

Estimate spend from active users, tasks per user, average usage by task, model mix, and retry rates. Keep assumptions and uncertainty visible.

Guardrail

Choose a response before the alert

Set thresholds by team or workload; specify whether the response is notify, throttle, route, require approval, or stop. Protect critical flows from surprise hard stops.

Ownership

Make allocation explainable

Assign a named owner and allocation method to shared usage. Review unallocated spend and avoid presenting estimates as invoice truth.

Value

Review unit economics regularly

Pair cost per request with cost per successful task, latency, quality, adoption, and business value. Revisit targets when workload mix changes.
